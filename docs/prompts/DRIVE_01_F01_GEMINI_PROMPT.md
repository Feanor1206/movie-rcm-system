## D1 acceptance details

The production path has no IO deadline today. Shared max-concurrent-streams permits alone are not Drive isolation: a blocked Drive stream consumes capacity used by local streams, and descriptor/HEAD can enter unbounded blocking metadata. Apply one coherent bounded policy across metadata/open/read and a provider-specific bulkhead/circuit. Choose finite configurable budgets with rationale; no unlimited queue/executor or per-read unbounded worker creation. Healthy local traffic and catalog must remain responsive during remote failures.

Do not claim Future.cancel(true) unblocks WinFsp/kernel IO. Track actual outstanding workers until real completion even after response timeout; a bounded number of stuck operations must lead to fast rejection, not unlimited worker replacement. Test tasks that ignore interruption and release them only with an explicit test latch. If true hard cancellation is unavailable, document that limit and enforce the resource bound. Keep successful streams efficient, random position reads, bounded buffers, cancellation/close and HTTP range/private behavior. Never read entire videos into memory or temp files. Errors before response commit should map to sanitized503/no-store; committed stream failure closes the body with accurate logging and no fake success. Exact implementation choice belongs to A/parent after contract review.
